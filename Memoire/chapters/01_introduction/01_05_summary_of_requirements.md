# 1.5 — Assessment Criteria and Evidence Boundaries

The answer to the research question rests first on whether the data path works as specified. A valid input should pass documented quality rules; an invalid input should stop before publication. Source lineage and run records should identify what was processed. Monthly billing should replace the corresponding provisional Daily period rather than duplicate it, and published totals should reconcile across the relevant layers. Analytical tables should retain clear grains and cost definitions so that the dashboard does not have to reconstruct every business measure from raw records.

Operational added value requires a separate assessment. Automated runs and reusable datamarts can be demonstrated from code and execution records. Whether a proposed view answers a FinOps question can be checked against its definitions and outputs. Restricted interactive access requires tests with representative application-owner and domain-manager identities across the dashboard, exports and direct data access; the presence of access-control features is not such a test. Similarly, a perceived performance improvement requires comparable timings for the existing and proposed reports.

The evidence available for this thesis is uneven. The local proof of concept has recorded reconciliation results for one synthetic monthly dataset. Cloud backfill and validation have been reported, but the corresponding executed versions, run identifiers and control outputs need to accompany any independently verifiable claim. No before-and-after series measures correction time, Power BI latency or the effort of the current cross-team process. Chapter 7 distinguishes implemented controls, observed results and tests still required. Chapter 9 discusses the organizational implications without presenting an unmeasured benefit as a proven outcome.
