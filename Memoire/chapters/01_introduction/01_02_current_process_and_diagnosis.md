# 1.2 — Current Reporting Process and Observed Difficulties

The existing Power BI Cloud Showback report is used by FinOps and management audiences. However, making a new source available, changing a cost calculation, adding a KPI such as a savings measure, or correcting a visual requires the FinOps team to contact the people who control the relevant data and reporting components. The team has limited direct access to the data platform and cannot independently inspect or change all stages of the process. Data Engineering and visualization consultants contribute the required technical expertise, but do not necessarily share FinOps' knowledge of the business rules. These tasks often need several exchanges before the requested result can be agreed and delivered. The consultants' locations describe how the work is organized; geographical distance alone has not been shown to cause delay.

The author also reports slow interactions with the current dashboard. Some data preparation and calculations take place inside Power BI rather than in subject-specific datamarts prepared for recurring FinOps questions. Moving suitable transformations upstream is therefore a design option examined in this project. It is not yet a measured diagnosis of the existing report: the contribution of its model, queries, visuals, source systems and capacity to the observed latency has not been isolated. Section 7.2 sets out the measurements that would be needed for such a comparison.

Distribution raises a separate problem. An application owner should see only the applications within that owner's responsibility, whereas a domain manager should see the applications in the relevant domain. Although some users already have dashboard access, interactive access with these scopes is not established for all intended recipients. For some requests, FinOps performs the analysis and sends a selected Excel extract instead. This provides an answer to a specific request, but each new question can require another manual step. The issue is the design and validation of the current access process, not an inherent inability of Power BI to restrict rows.

Finally, the author has encountered blank values, suspected indicator errors and visual defects in the existing reporting process. Their frequency and causes have not been measured. A missing source attribute, a calculation rule and a visual error call for different corrections, yet each can appear to the reader as an unreliable dashboard result. The central problem is therefore not only how quickly a visual can be changed. It is how FinOps can obtain trustworthy, reusable cost data and evolve reporting without losing control of definitions, access rights and publication.
