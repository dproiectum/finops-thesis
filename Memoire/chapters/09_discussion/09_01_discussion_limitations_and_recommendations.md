# 9.1 — Discussion, Limitations and Recommendations

The local validation establishes that the synthetic January 2025 data can pass the implemented processing and reporting path with reconciled row counts and billed cost. It also exposes a limitation of the analytical product: 95.98% of billed cost in that month is assigned to an `Unknown` cost center (Section 6.3). A reconciled total therefore does not, by itself, provide usable accountability. The allocation rules and source attributes need business review before the same measures can support managerial showback.

The project implements a versioned contract, a canonical Silver representation, a Gold model and subject-oriented datamarts. The independent generator makes the input reproducible. These properties support the reliability question in section 1.3 for the local tests. The Belgium plan reports a historical Databricks backfill, but its run identifiers and control outputs are not yet part of the thesis evidence package. A complete Daily promotion, monthly close and recovery test would address claims that the current local results cannot establish.

The governed self-service question remains less resolved. The local Streamlit application executes against datamarts, but the intended manager and analyst identities have not been tested across dashboard, export and direct SQL access. The existing Power BI dashboard already serves several manager groups according to the student's account. A future user study must therefore compare defined tasks and change requests, rather than assume that introducing another interface creates autonomy. Security and business approval remain conditions for any wider access.

Cost comparisons in chapter 6 are descriptive results from generated data. They do not show avoidable expenditure or savings at the host organization. Similarly, chapter 8 defines the platform cost boundary without a complete DBU, GCP and labor-cost dataset. The first economic recommendation is to record comparable workload costs and outputs; only then can Serverless, Classic, scheduling or retention changes be ranked. Performance tests must control input, revision, cache and compute configuration as set out in section 7.3.

The evidence has limited external validity because the detailed history is synthetic and the validated local dashboard covers one month. The construction demonstrates that the engineering method is testable, while actual billing semantics, utilization, user tasks and organizational benefit remain unmeasured. The next validation priority is to capture cloud run artifacts and access tests, then evaluate representative business scenarios on authorized data.

## Centralized production and domain use

The proposed model keeps shared ingestion, definitions and controls with the platform and FinOps functions while distributing access to approved products. This can support independent consumption without assigning production responsibility to each domain. The project has not tested whether such an arrangement shortens change requests. Section 9.2 examines an embedded Data Engineer as one possible response to the reported handoffs; its staffing cost and effect require measurement. The local single-domain prototype gives no evidence for adopting a full Data Mesh operating model.
