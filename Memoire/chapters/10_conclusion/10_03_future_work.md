# 10.3 — Future Work

The immediate technical extension is an evidence-backed cloud validation of the complete Daily-to-monthly-close cycle. It requires a DEV-to-PROD promotion, replay of an already processed file, reconciliation against a monthly billing candidate, and recovery from a controlled interruption. Retained run identifiers, table outputs and costs would also permit a controlled Serverless and Classic comparison. These tests address specific gaps identified in chapters 7 and 8.

Governed use first requires the planned Cloud Run persona experiment to test denial by default and role-and-scope filtering across every dashboard query. A production extension would replace the synthetic selector with a validated Google IAP identity, synchronize authorized users and groups with the enterprise directory, review entitlements periodically and retain sanitized access logs. The backend service principal should remain read-only and limited to the serving products and security metadata. If users later receive direct analytical access, Unity Catalog views, row filters or equivalent controls must protect the same scopes outside the dashboard. Representative manager and analyst tasks on authorized data would then test whether the products answer the intended questions and whether the change workflow improves compared with the recorded baseline.

Forecasting could be investigated after a target quantity or cost measure, forecast horizon and simple reference method are defined. Chronological validation on the synthetic history would test only behavior under the generator's assumptions. Evidence from representative real history would be needed before describing operational forecasting value.
