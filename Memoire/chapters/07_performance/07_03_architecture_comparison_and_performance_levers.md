# 7.3 — Architecture Comparison and Performance Levers

The local POC publishes fourteen materialized datamarts, eleven of which its Streamlit application queries. Section 7.1 establishes their functional execution and reconciliation for January 2025. It does not measure the latency benefit of materialization. An equivalent direct query and datamart query would be needed in the same environment, with identical answers and recorded cache state, to attribute a difference to this design choice.

Cross-system comparisons require further controls. The company's Power BI report and the synthetic local POC differ in data, engine, model, network and capacity. A raw timing difference between them would describe those particular settings rather than establish architectural superiority. Where access permits, query execution, application processing, rendering and end-to-end response should be recorded separately. Storage and refresh cost also belong in the comparison because a materialized answer may be faster to read but more expensive to maintain.

The repository defines Serverless and Classic Databricks scenarios with common processing logic. The earlier Serverless `STANDARD` setting and the Belgium Classic templates differ in compute and Job policy; the reported historical backfill does not resolve those differences experimentally. A controlled comparison would process the same source months and code revision into isolated outputs, verify result equality, and repeat runs with region, runtime, Photon, worker settings, concurrency and cache recorded. Startup time, total duration, DBUs and full provider cost would then be compared. No quantified Serverless or Classic advantage is currently supported by the project evidence.
